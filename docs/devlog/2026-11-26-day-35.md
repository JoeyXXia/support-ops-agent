# Day35 · 轻量回归门禁

北京时间 2026-11-26。Day34 已推送，开始时本地和远端 main 都为 `bb60804`，其 GitHub 离线工作流成功。项目已有全量离线、数据库和浏览器 CI，数据库套件包含身份隔离、审批及幂等测试，确定性评分随 Python 全量发现运行。真实模型只有此前的人工冒烟入口。

## 三组可独立审查的改动

1. `.github/workflows/ci.yml` 增加具名定向门禁。分离确定性评分、只读授权、真实 PostgreSQL 用户隔离、审批和工单幂等的失败信号，随后沿用全量步骤。
2. `.github/workflows/live-evaluation.yml`、`scripts/evaluate_day35_live.py`、`tests/test_day35_live_eval.py` 提供独立手动入口及模拟测试。选用三个冻结开发样例、给定合成证据和固定格式判分。复用 Responses provider，免去额外服务、工具与业务写入。
3. `docs/day-35-evaluation-review.md`、本文、`docs/scope.md` 和 `reports/day-35-validation.json` 记录第二篇复盘和验收证据。里程碑标签为 `v0.5-eval`。

## 五项可观察验收

- PR 和 push 仅启动离线路径。评分、租户授权、审批与幂等门禁在 GitHub Actions 可按名称定位，原有全量门禁保留。
- 在独立测试进程移除一次工作区租户过滤，定向负例产生一次断言失败。恢复后同一用例通过。仓库里保留原权限条件。
- 手动流程限定 `main` 且确认框默认关闭。请求采用其专用凭据，无凭据时退出码 2、请求数 0。
- 三条合成 QA 最多三次串行请求，每次最多 1,200 字节提示词、32 输出 token、20 秒超时。首次 provider 错误即停止。通过模拟验证正确、错误和中止分支；usage 仅采用响应返回值。
- 发布前复核所测版本，正常推送 `main` 和 `v0.5-eval` 标签，并核验标签指向经检查的 main 提交。
