# Day 17 工单模型与动作草稿

2026-11-12，北京时间。开始时工作区干净，本地与远端 main 均为 `ebda0da48a45c67d5ca28ed2fafd3a5bd42cd49b`，对应已验证、已推送的 Day 16。

## 当前实现与最小方案

此前已有只读排障、引用问答、LangGraph 状态机和 PostgreSQL 恢复能力。工单只存在于合成样例文件，业务库尚无工单或审批表。本日新增持久化工单和待审核动作，沿用服务端身份、现有工具注册表和数据库。

三个独立审查单元如下。

1. 数据模型与受控执行。`migrations/versions/0004_tickets.py`、`packages/storage/schema.py` 和 `packages/storage/tickets.py` 建立 tickets、approvals 表。必填字段包括租户、工作区、标题、描述和请求人。工单状态为 open/closed，审批状态为 pending/approved/rejected/executed。审批绑定已有 run，保存精确参数。每个 run 的同种动作只有一个草稿。受控 `create_ticket` 读取服务器保存的参数，锁定审批行，要求 approved，再在同一事务中建单并标记 executed。
2. Agent 工具与运行绑定。`packages/tools/schemas.py`、`executor.py`、`packages/agent/loop.py`、`ticket_mock.py`、`persistence.py` 注册 get_ticket 和 propose_ticket。get_ticket 按获授权租户查询。草稿工具的参数只有 workspace_id、title、description，租户由获授权工作区推导，run ID 由执行器注入。运行结果中的 proposed_action 来自工具返回值。
3. API、展示与验证。`apps/api/main.py`、`runs.py`、`persistent_runs.py` 和 `apps/web/src/App.tsx` 提供显式草稿演示模式，展示目标租户、工作区、动作、标题、描述和状态。`POST /tickets` 只接收 approval_id。测试在 `tests/integration/test_tickets.py`，表单及草稿长文本样式在 `apps/web/src/style.css`，已有注册表和迁移表集合断言同步更新。报告保存到 `reports/day-17-validation.json`。

## 五项验收与实测

- 实际 Agent 与 API 生成草稿后，数据库工单数为 0、审批数为 1，审批为 pending。待执行的描述与输入问题一致。
- Edge 浏览器实际提交后显示服务器返回的精确参数及目标租户，草稿状态为 pending。该 run 的审批数为 1，演示库工单数为 0，实际建单请求返回 409。演示固定针对 ws-alpha，生成采用确定性 mock。
- 普通用户读取其他租户工单和读取不存在的工单，工具返回相同的 not_found，正文不会返回。
- 同一 run 重复提出相同草稿返回同一审批 ID。更换参数被拒绝，原草稿保留。未批准草稿的受控建单返回 409，额外传入 status 被请求验证拒绝为 422。
- 模型的 create_ticket 调用返回 unknown_tool。完整离线门禁 71 项、真实 PostgreSQL 集成 27 项通过，前端格式检查与 TypeScript/Vite 构建通过。

受控执行的正向测试只在专用测试库里由 SQL 测试夹具设置 approved，随后核对建单内容和重复执行结果。该测试不代表批准流程已交付。公开批准、拒绝及参数摘要和有效期绑定属于 Day 18。

## 复现与边界

按 README 配置本机数据库并执行 `python -m alembic upgrade head`，设置 `SUPPORTOPS_PERSIST_RUNS=1` 后启动 API 和网页，勾选待审核工单草稿。API 可提交 `POST /runs`，请求包含 `question` 与 `ticket_draft: true`，随后 GET 原运行 ID 查看 proposed_action。草稿模式与文档引用模式互斥，内存运行模式提交草稿返回 409。

对显式专用 `_test` 数据库设置 TEST_DATABASE_URL，运行 `python -m unittest discover -s tests/integration -p test_tickets.py -v`。测试使用独立 schema，验证草稿数量、跨租户读取、不可伪造身份和状态、受控建单以及 API 查询。完整命令和输出见验证报告。

最可能失败的边界是恢复时重跑草稿工具，以及模型尝试替换目标租户、run 或批准状态。数据库唯一约束和参数比较让相同提议复用已有草稿，变化提议返回工具错误。模型参数验证拒绝身份和批准字段，建单能力未注册为模型工具。数据库或迁移未就绪时草稿无法保存。当前 API 仍使用固定本机演示身份，完整登录尚在计划中。

本轮首次数据库验收因本机 PostgreSQL 未启动而在测试开始前超时，随后启动已有运行时。离线门禁的旧工具列表断言也按本日新增工具更新后重跑。所有结果采用合成数据与 mock，未调用付费 API。
