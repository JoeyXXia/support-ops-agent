## 当前实现与最小方案

Day 18 已把用户、run、参数摘要和期限绑定到审批，建单时锁定审批行，同一事务插入工单并标记 executed。重复执行通过 ticket_id 读取现有工单。本日增加明确的动作 key 和持久化结果快照，核对并发、部分失败、响应丢失和升级后的行为。

三个审查单元如下。

1. 结果表与历史迁移。`packages/storage/schema.py` 和 `migrations/versions/0006_action_executions.py` 增加 action_executions。approval_id 为主键，租户与 idempotency_key 联合唯一，ticket_id 唯一。保存参数摘要、结果 JSON 与记录时间。迁移为已有 executed 审批建立升级时可见的结果快照。
2. 受控执行与 API。`packages/storage/tickets.py` 以 `create_ticket:<approval UUID>` 定义一个逻辑动作的稳定 key，归属校验后核对 key、参数和已有回执。新写入将工单、审批状态、执行结果放在一个事务中。`packages/tools/schemas.py` 的草稿结果包含动作 key。`apps/api/main.py` 的建单请求可附带 idempotency_key 和 payload_digest，也支持只传 approval_id 并由服务器推导 key。
3. 验证与记录。`tests/integration/test_idempotency.py` 覆盖重试、并发、丢失响应、新进程、回滚和历史迁移，现有迁移表集合断言同步更新。README、scope 与验证 JSON 记录复现方法。

## 五项可观察验收

- 首次 API 建单后顺序重试 10 次，共 11 次成功响应完全相同，数据库保持 1 条工单、1 条回执。成功执行的审批即使随后过期，也能读取原回执。
- 8 个线程通过独立数据库事务并发执行同一审批，返回同一结果，仍只有 1 条工单、1 条回执。额外直接尝试重复联合 key，命中命名唯一约束 uq_execution_action_key。
- HTTP 测试传输层在真实 API 已返回并提交后主动丢弃响应，客户端收到 ReadError。关闭该 API 生命周期后，启动全新 Python 进程重试，得到保存的结果，数量保持 1/1。
- 相同 key 携带不同摘要、指向不同审批，以及成功后实际参数被改写的情况均被拒绝。API 返回 409，已有结果保留。工单资源状态改变后，重试建单返回原执行快照，get_ticket 可读取资源当前状态。
- 数据库触发器分别在审批状态更新和回执插入处注入异常。失败后工单与回执数量均不增加，审批保持 approved 且 ticket_id 为空。移除故障后重试成功。已有 executed 数据经过降级至上一版再升级，回执回填并复用现有工单。

## 事务与失败窗口

| 写入安排或失败点 | 影响与当前处理 |
| --- | --- |
| 分别提交成功状态和建单 | 第二步失败会留下成功状态与业务事实不一致 |
| 分别提交工单和成功状态 | 第一次响应或状态写入丢失后，重试可能再次插入 |
| 当前事务在状态或结果写入前失败 | PostgreSQL 回滚该事务，工单、状态和回执一起回到写入前 |
| 事务提交后响应丢失 | 同一 key 重试时返回保存的结果 |

客户端可以按至少一次方式重试。同一审批动作在当前 PostgreSQL 事务边界内保持一条工单和一条执行回执。新的 run 会生成新的审批及动作 key。回执是执行结果快照，当前资源内容通过读取工具查询。

## 复现与边界

执行 `python -m alembic upgrade head`，在持久模式生成并批准新草稿。GET 原 run 可取得 proposed_action 中的 approval_id、idempotency_key 与 payload_digest。将这些字段提交到 `POST /tickets` 并重复请求，核对返回的 ticket_id 及结果一致。

设置显式 TEST_DATABASE_URL，驱动为 postgresql+psycopg，专用库名以 `_test` 结尾，运行 `python -m unittest discover -s tests/integration -p test_idempotency.py -v`。测试为每个方法建立独立 schema，使用真实 PostgreSQL 约束及触发器，结束后清理。并发证据为同一受控建单服务的 8 路数据库调用，HTTP 顺序和响应丢失证据使用 ASGITransport。完整回归命令为 `python scripts/check_offline.py` 与 `python -m unittest discover -s tests/integration -v`。

最可能的失败边界是提交成功后客户端未收到响应。调用者重用原审批与 key 查询结果。过期、拒绝或未经批准的动作仍不能首次建单，归属校验发生在回执查询前。本轮沿用现有 PostgreSQL、API 和依赖，身份仍为固定本机演示身份，数据均为合成样例。
