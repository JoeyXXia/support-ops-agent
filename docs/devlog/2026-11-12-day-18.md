## 当前实现与最小方案

Day 17 已能生成绑定 run 的工单草稿，展示参数和目标租户，按租户读取工单。受控建单只检查 approved 状态，公开批准和拒绝流程尚未建立。本日复用现有审批表、PostgreSQL checkpointer 和 LangGraph，补齐决定的可信来源与执行校验。

三个审查单元如下。

1. 审批绑定与迁移。`migrations/versions/0005_approval_binding.py`、`packages/storage/schema.py`、`tickets.py` 与 `packages/tools/schemas.py` 增加 payload_digest、expires_at、decided_by、decided_at。规范化 JSON 的 SHA-256 摘要覆盖 run、目标租户、请求人、动作和精确参数。新审批有效期默认 30 分钟，批准和执行时均核对服务器数据库时间。旧草稿保留可读，缺少绑定信息的审批失效，需要新建运行重新生成。
2. 决定接口与图恢复。`apps/api/main.py` 增加 approve/reject 接口，请求只允许 run_id 和 payload_digest。服务端校验归属、摘要、状态与期限后保存决定并恢复原 run。`packages/agent/graph.py`、`loop.py`、`persistence.py` 和 `apps/api/persistent_runs.py` 增加 awaiting_approval、await_approval 和 execute，使用现有 checkpointer 的 interrupt/Command 继续执行。建单节点再次读取并验证数据库审批，模型输出与恢复信号均不充当授权。
3. 网页与验证。`apps/web/src/App.tsx` 展示到期时间，提供批准并创建工单和拒绝草稿，显示工单 ID 与错误原因。`tests/integration/test_approvals.py` 验证正常流程和失效边界，已有 Day 17 测试适配等待状态及审批人绑定。README、范围与本报告记录复现方法。

## 五项验收与实测

- 批准后，运行从 awaiting_approval 恢复，路径末尾为 await_approval → execute → done，返回已创建工单。拒绝后流程完成，ticket 为空，数据库工单数保持不变。重复相同决定保持结果，拒绝后再批准返回 409。
- 其他用户或租户无法决定审批，错 run 返回不可访问。请求摘要不匹配被拒绝，客户端身份或批准字段不能替代服务端上下文。
- 过期审批不能批准，已经批准但在执行前过期也不能建单。批准后改动保存参数会触发摘要校验失败。只改状态为 approved、未保存可信决定人和时间，同样无法建单。
- 模型输出“已批准”时图仍等待审批。测试额外伪造内部恢复信号，受控节点仍因缺少数据库授权而拒绝，工单数为 0。修改参数需要新 run 和新审批，原审批不重写。
- 71 项离线测试、32 项 PostgreSQL 集成测试及前端格式和 TypeScript/Vite 构建通过。新增重启用例先保存批准决定，关闭并重新建立 API 生命周期，再按原 run 恢复，成功创建 1 条工单。

Edge 浏览器实际生成两次新运行，分别点击批准和拒绝。页面核对等待状态、到期时间、工单 ID 和拒绝结果，API 终态及数据库计数同步核对，两次操作合计新增 1 条工单。等待、批准和拒绝截图保留在本地 output/playwright，实际运行与回执写入验证 JSON。首次浏览器会话在操作前关闭，重建后完成验收。

## 复现

安装已有锁定依赖并执行 `python -m alembic upgrade head`，启用 `SUPPORTOPS_PERSIST_RUNS=1`。网页生成新工单草稿，等待审批后核对精确参数和北京时间到期时间，再选择批准或拒绝。

API 先提交 `POST /runs`，包含 question 与 ticket_draft，GET 原 run 取得 proposed_action。向 `POST /approvals/{approval_id}/approve` 或 `/reject` 发送原 run_id 与 payload_digest，然后轮询 GET 原 run。若决定已保存但恢复请求失败，可重新发送同一决定或调用 `POST /runs/{run_id}/resume`。修改问题后重新提交运行会获得新审批，已有草稿的参数不可原地替换。

设置显式专用 TEST_DATABASE_URL，库名以 `_test` 结尾，运行 `python -m unittest discover -s tests/integration -p test_approvals.py -v`。完整回归使用 `python scripts/check_offline.py` 和 `python -m unittest discover -s tests/integration -v`。集成测试使用独立 schema，不以 SQLite 或 mock 数据库替代 PostgreSQL。

## 失败边界与限制

最可能失败的边界是批准决定已提交、图尚未完成恢复时服务退出。决定与图状态分别保存在业务表和检查点中，原 run 可以继续恢复，执行时重新校验当前审批。数据库时间超过有效期会使尚未执行的批准失效。已执行动作的重复查询复用已有结果。

当前 API 仍使用固定本机演示身份。审批者与请求人必须匹配，并且与原 run 的完整身份上下文一致。生成采用确定性 mock，全部案例使用合成数据。30 分钟有效期及修改参数时新建 run 是本日采用的最小实现选择。旧版未绑定草稿通过新运行重新申请审批。本轮沿用既有依赖与服务。
