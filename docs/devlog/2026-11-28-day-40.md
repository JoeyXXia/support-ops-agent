# Day40 · 用量、成本与缓存

北京时间 2026-11-28，手动推进一个 Day。开始时本地与 GitHub main 均为 `ddda5c3`。原 provider 已能解析供应商 usage，运行不保存逐次来源或金额。文档入库已有 embedding 缓存，查询仍每次计算检索与上下文。

## 三组可独立审查的改动

1. `packages/agent/costs.py`、原生循环和 LangGraph 增加逐次用量和估算账本。首次执行时固定价格日期与预算配置，随图检查点保存。已有 API 和 SSE 发布账本。
2. `packages/knowledge/search_cache.py` 与现有只读工具增加短时进程内证据缓存。检索重用最新适用版本查询，在 PostgreSQL 同一快照中检查修订和计算结果。已有 embedding 缓存保留。
3. 增加 mock 会计、真实 PostgreSQL 持久化和缓存隔离回归，记录复现与实测。

## 五项可观察验收

- 输入、输出和来源逐次保存。供应商模式的注入响应与 mock 夹具使用不同来源标签。日期选取不使用未来价格。
- 缺价格、usage 或失败尝试累计金额未知。配置预算时，估算达到上限或本次量价未知会停止后续步骤。持久运行通过 GET 和 SSE 返回相同账本。
- 同租户与版本的同查询第一次未命中，第二次命中，证据一致。
- 切换租户、产品版本或 embedding 模型不复用先前结果。
- 导入未就绪的新适用修订后，旧证据不可用。新修订就绪后首次未命中并返回新版，随后命中。已有 embedding 作用域和提供商隔离验证继续通过。

主要边界是把未知记成零、把估算当作账单、缓存跨租户或绕过新修订。账户估算不包含失败调用中无法确认的 usage。预算在取得响应后判断，不能封顶该次已经发生的请求。没有实时计费结果，本轮金额仅来自合成测试目录。

证据缓存最多 128 条、每条 60 秒。键包含数据库与 schema、租户、产品版本、embedding 提供商及模型、切块与输入版本、查询哈希，以及最新文档版本与 PostgreSQL 行版本。导入和入库走原有入口，行版本和检索使用同一个事务快照。即使缓存命中也会查版本，不缓存最终答案。

## 实测

- 会计单测 3 项通过。15 个合成 token 按测试目录估算 0.02 USD，预算等于估算时停止，工具调用数为 0。缺价格或失败且没有 usage 时金额为未知，开启预算后不继续执行。
- PostgreSQL 的缓存与 embedding 作用域专项 2 项通过（1.149 秒）。全量回归 61 项通过（73.293 秒）。随后补跑的预算持久化专项 1 项通过（0.970 秒），GET 和 SSE 返回相同账本。
- Python 离线 130 项通过（52.110 秒）。Day34 冻结开发集仍为 29/60。真实模型调用为 0，价格和 token 数来自测试夹具。
