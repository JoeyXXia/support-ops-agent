# Day 16 检查点与重启恢复

2026-11-11，北京时间。开始时 main 工作区干净，本地与远端均为 `330d6b667590edebe8c69f97aca96f6d3d9fcf35`，对应已验证推送的 Day 15。

## 当前实现与最小方案

Day 15 使用 LangGraph 编排只读排障与引用问答，图状态包含带回调的 AgentTurn 实例，运行记录保存在单进程内存。本日把每个节点的完整进度转换为可序列化快照，复用 PostgreSQL 保存官方 checkpointer 数据，再增加运行归属与显式恢复入口。

三个审查单元如下。

1. 图状态与检查点。修改 `packages/agent/graph.py`，新增 `packages/agent/persistence.py`。保存请求消息、模型响应、可信上下文、预算计数、已见调用、当前证据、事件与路径。每个节点提交新快照，回调从当前进程绑定。使用官方 PostgresSaver，其异步方法通过线程桥接以适配 Windows。依赖和锁文件增加 PostgreSQL 检查点适配器。
2. 运行注册与 API。新增 `0003_agent_runs` 迁移并同步表定义，修改 `apps/api/main.py`、`runs.py`，新增 `persistent_runs.py`。`agent_runs` 保存运行 UUID、租户、用户、身份上下文、不可变输入配置和查询记录。一个 run 对应一个同名 thread。先校验归属再访问检查点。事务级 PostgreSQL advisory lock 保证同一运行只有一个恢复执行者，进程退出后数据库释放锁。
3. 故障验证与文档。新增 `scripts/checkpoint_run.py`、`tests/integration/test_checkpoints.py`，更新已有迁移表集合断言、环境变量模板、README 和页面说明文字，保存实测报告。

## 五项可观察验收

- 在模型调用前、模型返回但节点尚未落盘、只读工具已完成三处暂停子进程，实际 kill 并 wait，然后由全新进程恢复。三种情况均完成 429 排障，终态为两次逻辑模型调用、两次逻辑工具调用、四条事件，答案含 60/60，路径为 classify → call_tool → classify → answer → done。
- 完成运行后关闭并重新进入 API 生命周期，GET 原 ID 得到相同记录。持久层已有 queued 运行可通过恢复接口完成，终态重复恢复返回相同结果。
- 其他租户的运行在实际 HTTP GET 和恢复接口均返回 404。服务层在检查点访问前拒绝其他租户。查询同时核对用户与完整可信身份上下文。
- 同一本地运行重复恢复返回 409。持有数据库运行锁时，第二执行者得到 RunBusy，记录仍为 queued，节点尚未开始。
- 完整离线门禁 71 项、PostgreSQL 集成 23 项及 pip 依赖检查通过。前端 Prettier 与 TypeScript/Vite 构建通过。清理持久模式已结束的内存缓存后，另行重跑三项恢复集成测试并通过。完整命令、耗时与输出保存在验证 JSON。集成测试中的一个方法包含三个独立进程终止子场景。

## 故障位置与恢复行为

| 退出位置 | 已持久化内容 | 恢复行为 |
| --- | --- | --- |
| 第一次模型调用之前 | 初始输入检查点 | 重跑 classify |
| 模型已返回，classify 尚未提交 | 前一个节点检查点 | 重新调用模型 |
| 工具批次中途 | classify 的工具提议 | 整个只读批次可能重跑 |
| 工具节点完成且已落盘 | 工具输出、预算、调用去重、事件 | 从下一次 classify 继续 |
| done 落盘后、运行摘要更新前 | 完整终态图状态 | 从检查点重建查询记录 |

前三组实际终止覆盖表中第一、第二和第四种情况。工具批次中途与摘要更新间隙的进程退出仍属已分析边界。检查点间的重放可能再次发起模型或工具请求，预算与事件中的计数表示已保存的逻辑执行。本轮使用确定性 mock，全部数据为 CloudDesk 合成数据。

## 复现与限制

按 README 先迁移数据库，再设置 `SUPPORTOPS_PERSIST_RUNS=1` 启动 API。官方 saver 的 `setup()` 在持久模式启动时准备其独立检查点表，业务归属表由 Alembic 管理。默认内存模式的健康检查和 mock 保持离线可运行。

设置显式专用 `TEST_DATABASE_URL`，驱动为 postgresql+psycopg 且库名以 _test 结尾。运行 `python -m unittest discover -s tests/integration -p test_checkpoints.py -v` 可复现子进程 kill、新进程恢复、API 重启与租户拒绝。测试为每个方法创建独立 schema 并在结束后清理。完整回归使用 `python scripts/check_offline.py` 与 `python -m unittest discover -s tests/integration -v`。

最可能失败的边界是数据库连接或迁移未就绪，以及节点完成与检查点持久化之间退出。持久模式运行由显式 POST 恢复，进程突然退出后摘要可仍显示 running。API 的可信身份仍为固定本机演示用户，完整登录接入留在后续计划。操作员 CLI 的故障开关只供本地验证。检查点保留完整消息及工具结果，版本升级前需要考虑快照兼容与保留策略。

首轮实测发现 LangGraph 无 checkpointer 时强制 sync durability 导致内部属性错误，以及 Psycopg async 与 Windows Proactor 事件循环冲突。前者按是否配置检查点选择落盘策略，后者使用官方同步 saver 在线程内执行，通过最终回归验证。
