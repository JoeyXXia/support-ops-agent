# Day30 确定性评分器

北京时间 2026-11-23，用户请求继续下一日时，本地和 GitHub main 均为 141c47d，工作区干净。Day29 已冻结 120 条，保留原分区及哈希。此前检索评估独立存在，缺少连接工具尝试与数据库证据的行为评分。

## 实现分组

1. `evals/behavior.py` 按工具注册表验证选择和参数，核对重试、步骤预算、终态、实际写入行数和工单状态。检索作为独立维度。
2. `tests/test_behavior_scoring.py` 和 `tests/integration/test_behavior_scoring.py` 验证正反例及真实 PostgreSQL 的拒绝和批准流程。
3. `scripts/score_day30.py` 将校准输入绑定到冻结开发集，按观察导出结果和原因。报告、说明和复现命令保存在 `evals/day30` 与 `reports`。

## 可观察验收

- 错用工具、布尔 limit、合法但错误的 limit 分别报告不同失败原因。
- 超步数或实际重试次数预算失败；同一 call_id 的有序失败重试不伪造逻辑调用。
- 缺持久证据、已写两张工单、工单状态不符或回执缺失均判失败。
- 真实 PostgreSQL 中，批准且持久化一张工单通过，拒绝且零工单通过。把零工单观察的返回状态改成「已建单」仍判失败。
- 按样例导出，可复现同一文件。检索指标独立输出，未标注样例排除，最终集不参与校准。

## 实测

11 条校准观察中，4 条正常对照通过，7 条故意构造的错误均被识别，重新导出的 JSON 字节一致。完整离线复跑 119 项通过（59.428 秒）。真实 PostgreSQL 全量 46 项通过（67.009 秒），在最终评分规则收紧后又单独复测真实批准、拒绝和零写入假成功用例，通过（1.143 秒）。

便携 PostgreSQL 原别名无法启动，本轮使用已安装 Docker 和 pgvector 现有版本启动回环随机端口的临时 `supportops_test` 容器，验证完清理。首轮离线和集成并行运行时，旧 MCP 故障夹具未在期限内到达断连注入点，119 项中 1 项失败；完整离线门禁随后单独运行。未改变原故障夹具等待值。

边界是受控运行器需采集完整真实参数和独立数据库观察。评分器无法从浏览器的精简 SSE、回答措辞或 HTTP 响应推断这些证据。人工质量评审、完整分区的模型表现和生产指标不属于本轮。真实 API 调用为 0。
