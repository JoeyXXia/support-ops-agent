# Day 3 — 模型边界、mock与OpenAI适配

日期：2026-11-01（Asia/Shanghai）。状态：实现与离线验收完成；真实调用成功验收被API余额耗尽阻塞。

## 三个审查单元

1. packages/agent/models.py：统一消息、请求、函数工具定义、调用参数、usage、响应和错误；ModelProvider协议定义异步generate边界。MockProvider提供确定性响应，明确mode=mock，无虚构usage。
2. packages/agent/providers.py：官方AsyncOpenAI/Responses适配，函数参数解析为JSON对象，拒绝无效、未知、空或未完成输出；20秒总超时、禁用SDK自动重试、请求不存储。配置通过根目录.env.local在服务端加载，使用后关闭客户端。
3. tests/test_providers.py、scripts/model_smoke.py及报告：标准库unittest验证成功映射、请求选项、配置缺失、超时、HTTP错误、函数调用和异常输出。离线测试不需要真实凭据；只有显式--live会调用API。

## 实际过程与结果

OpenAI SDK 3.42.0、python-dotenv 1.2.4及传递依赖已锁定。未引入Agent框架、数据库、前端模型调用或业务工具。服务端密钥经用户确认创建并保存到被Git忽略的.env.local，有效期7天；报告不记录密钥值。

- mock命令可离线运行，并显式标记mock。
- 7个unittest方法通过；HTTP分支包含临时429、insufficient_quota、credit_balance_exhausted、嵌套额度错误、401、403、500，共7种情况。超时测试确认只调用一次；错误字符串不包含上游正文。
- 初次真实请求：gpt-4.1-mini、32输出token上限、无自动重试，返回429。当时适配器将未识别的余额错误归为临时限流。
- 第二次诊断请求：同模型、16输出token上限、无自动重试，得到code=credit_balance_exhausted、type=insufficient_quota。已据此修正额度分类，并补充回归分支。没有继续发送真实请求。
- 两次请求均未获得成功答案。没有可报告的成功usage、成本或质量指标；绝不把离线注入响应算作真实模型结果。

安全原始元数据见 ../../reports/day-03-live.json；结果摘要见 ../../reports/day-03-validation.json。第二次诊断只用于识别错误类别，不代表适配器完整成功路径已通过live验证。
