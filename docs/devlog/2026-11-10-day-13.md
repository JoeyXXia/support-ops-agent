# Day 13 引用回答与知识不足处理

2026-11-10，Asia/Shanghai。基线提交 `0fbe8bf`。Day 12 已有有界的检索上下文和来源定位，原 Agent 与网页支持本机 429 排障演示。

## 三个审查单元

1. `packages/tools/schemas.py`、`packages/tools/executor.py`、`packages/tools/knowledge.py` 注册受限的 search_docs。租户来自经过核对的服务端身份，检索先按允许范围和产品版本过滤，然后组装预算内片段。
2. `packages/agent/grounding.py`、`packages/agent/loop.py`、`packages/agent/knowledge_mock.py` 加入结构化状态和引用校验。只解析最近一次成功检索的上下文，来源元数据和摘录由服务器组装。
3. `apps/api/main.py`、`apps/api/runs.py`、`apps/web/src/App.tsx` 加入文档演示选项和可展开来源，保留既有 429 流程。测试和报告随本轮提交。

## 可观察验收与结果

- 受控测试中，当前上下文内的引用得到逐字摘录，伪造或上一次检索的引用均失败，答案和引用列表不泄露旧证据。
- 五个固定问题经本地 PostgreSQL 和真实网页流程得到目标出处。Playwright 在 Edge 中逐个点开来源，核对可见摘录、产品 2.0、修订 1、路径和行号。
- 缺版本时直接追问，工具调用为 0。无匹配证据时提示无法确认，引用列表为空。Edge 覆盖了两种界面，测试另覆盖同名来源正文冲突。
- 逐条复核 10 个 API 示例，其中 5 条为有引用的摘录，3 条为依据不足，2 条为缺版本追问。五条摘录均核对了实际文档正文。分钟限流例引用等待 Retry-After 的通用规则，当前摘录没有额外生成「等待 20 秒」这类个性化结论。用户人工复核尚待进行。
- 离线门禁 70 项、真实 PostgreSQL 集成 20 项通过。前端 Prettier 检查和 TypeScript/Vite 构建通过。

## 复现与边界

按 README 启动本机 PostgreSQL、API 和网页，使用文档引用演示输入五个固定问题。来源 ID 校验保证出处属于本轮授权上下文，语义支持度仍须检查。冲突只按已召回的同名来源正文差异作保守处理。本轮生成由确定性 mock 选来源，服务器逐字摘录。更广泛的问题覆盖和真实模型生成仍待验收。
