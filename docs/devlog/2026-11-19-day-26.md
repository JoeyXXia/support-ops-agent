## 当前实现摘要与最小方案

Day25 已有独立官方 SDK stdio server、两个工作区只读工具和可信启动主体；网页 Agent 仍直接执行工具。今天给既有执行器增加异步调用边界，新增固定本地 MCP adapter，让后端可选 direct/mcp。保留现有身份、工具 schema、调用预算、错误分类和审批事务；不新增依赖、服务、迁移或前端控件。

## 三组可独立审查改动与涉及文件

1. 执行与传输：`packages/tools/executor.py`、`mcp_adapter.py`、`routing.py`、`packages/agent/loop.py`。默认 direct，MCP 仅处理 get_workspace_usage/get_recent_errors；固定解释器、模块、目录，校验 server 名和两项工具的输入/输出 schema。其余工具沿用本地执行。
2. 可信配置与验证：`apps/api/runs.py`、`events.py`、`packages/agent/persistence.py`、`tests/test_mcp_adapter.py`、`tests/fixtures/mcp_fault_server.py`、`tests/integration/test_mcp_routing.py`。后端环境选择路径，run 保存只读传输元数据，恢复使用原模式，旧记录缺省 direct；正文和模型不能选择传输。验证真实 stdio、会话主体、预算、故障及真实数据库兼容。
3. 说明与证据：`.env.example`、README、`docs/scope.md`、`docs/mcp.md`、本日志和 `reports/day-26-validation.json`。记录操作、信任边界、实测及限制。

## 五项可观察验收

- 原生 AgentLoop、LangGraph 和 HTTP ASGI 的同一 mock 429 主流程可切换 direct/mcp；答案、工具输出及状态路径一致，正常调用次数均为2。MCP 使用真实官方 SDK 子进程，不将 FakeClient 当作跨进程验证。
- HTTP 会话的不可变 AuthContext 传到 adapter；启动主体由其 user_id 派生，并先严格比对完整租户、角色、support 分配。即便全局独立 server 主体设为 alpha，beta 会话读取 alpha 工作区仍失败；伪造参数、角色和授权范围在启动前拒绝。
- 固定 server/工具/schema 白名单；额外工具广告、非法结果、isError 与 envelope 不一致为不可重试 internal_error。只消费严格 structuredContent，不转发任意文本工具说明或错误详情给模型；授权仍由 server 内业务层再次执行。
- 真实子进程接到工具后挂起或退出，分别返回 retryable timeout/unavailable；显式取消向上传播。FakeClient 另验证既有三次尝试及工具调用预算生效，没有静默回退 direct。
- PostgreSQL 中保存的 mcp/direct 模式不受后续环境更改影响；缺少字段的旧记录继续 direct。MCP 模式下 propose_ticket、批准后建单和 search_docs 引用仍使用本地工具及原事务，真实数据库验收通过。

## 实测结果与复现

110项离线测试通过（含8项新增适配器测试），45项真实 PostgreSQL 集成测试通过（含2项新增传输模式验收），pip check通过。离线门禁命令耗时56.094秒，数据库回归命令耗时54.515秒；它们是本机单轮命令耗时，不是生产性能指标。

真实挂起工具在3秒请求期限下返回 timeout，含 SDK 清理实际5.031秒；真实退出工具返回 unavailable，实际1.438秒。显式取消测试通过；测试后未发现本次 MCP server/故障夹具残留进程。故障重试预算使用明确标记的 FakeClient；主流程、故障子进程及数据库验收均有真实执行。


数据库测试仅允许 postgresql+psycopg 和名称以 `_test` 结尾的专用库，每项使用唯一 schema 并清理。报告保留首次失败及最终通过的命令、退出码、耗时和原始输出；URL、口令和私有数据不写入报告。

## 失败修正与主要边界

首次数据库验收因本项目便携 PostgreSQL 尚未启动而连接超时，0项执行，未视为通过。确认已有 ASCII junction 指向本项目 output/day8-runtime 后，按原文档仅启动 127.0.0.1:55432 集群，再运行相同测试；未使用其他项目数据库。后续验收进程显式加5秒连接等待，命令外层设300秒上限。开发中的过长注释已修正，最终以质量门禁结果为准。

默认单次 MCP 请求期限5秒，涵盖连接、发现与调用；初始化器只接受有限的0–10秒范围（不含0）。SDK 清理子进程会增加实际等待，不能把请求期限写成端到端总耗时。注入测试证明工具已到达（落盘 marker）后才观察超时/退出，单次测量不代表生产 SLA、吞吐或平均延迟。已有 Agent 最多三次尝试、工具预算及步骤期限继续约束调用；取消不当作可重试业务失败。

当前仅支持四个静态种子主体。adapter 只有在完整上下文与本地 server 可表达的身份完全相同时才启动；support 分配为空、额外或不同均拒绝，不能只凭 user_id 重新派生而扩大权限。未来动态分配需要新机制，不能直接复用本地名字当认证。拥有本机代码/启动权限的人仍在信任边界内。

每个 MCP 读调用打开并关闭一个短生命周期进程，没有连接池或多租户共享进程；启动开销未单独做基准。固定子进程读取仓库合成数据，不支持自定义 executor 数据目录跨进程复制。应用配置不能指定命令或 URL；仅测试夹具通过 mock 替换启动参数注入故障，业务入口无法选择它。

模型仍为确定性 mock，MCP 协议和 PostgreSQL 为真实执行；未请求付费模型或 embedding API，未测真实模型质量。没有新增框架或依赖；requirements.lock/pyproject 未改。没有远程 HTTP/OAuth、任意第三方 server、MCP 写工具、Day27 Compose/E2E，也没有前端或浏览器验收声明。
