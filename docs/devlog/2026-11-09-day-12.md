# Day 12 重排与上下文组装

2026-11-09，Asia/Shanghai。基线提交 `59f0389`。Day 11 CLI 已提供带出处和修订定位的向量、BM25、RRF 候选，以及证据命中评测。

## 审查单元

1. 在 `packages/knowledge/context.py` 复用现有 BM25 对候选重排，保留未匹配项的原顺序，异常时回退到完整原排名。
2. 在同一模块组装引用上下文，并在 `scripts/search_documents.py` 接入显式上下文与重排开关。
3. 在 `evals/retrieval.py` 加入开关对照，增加预算和故障回归，并保存逐例数据、命令和本报告。

## 验收与边界

- 默认按检索顺序组装。显式启用时重排并标记 applied，注入故障时标记 fallback，来源和顺序与关闭模式一致。当前实现为本地词项重排，外部重排模型留待独立验收。
- 读取至多 20 个既有授权候选，默认最多保留 5 段。相同 chunk ID 或空白归一后正文相同的片段只保留一次，正文中保留 chunk ID，sources 保留出处、修订及原文位置。
- 默认以 2048 UTF-8 字节为正文预算，含引用标记和分隔符。它用于常见按字节编码的模型场景的保守估算，实际 tokenizer 计数和完整提示开销需在生成阶段独立核算。超预算片段整段跳过，允许后续短片段进入。查询超过 8192 UTF-8 字节时拒绝，1 字节预算实测返回空上下文。
- 质量与耗时对照使用同一 PostgreSQL 快照。两组逐例候选 ID 及顺序实测一致，Day 11 的三路逐例评测保持一致。新增单测覆盖多字节及引用开销、空预算结果、重复证据、长度上限和故障降级。
- 候选阶段的漏召回无法靠本重排恢复。词项打分可能偏向字面重合，整段预算策略可能跳过相关长片段。最终引用 ID 必须以 sources 返回值为准。
