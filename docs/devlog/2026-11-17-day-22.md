# Day 22 — 种子账号会话与资源隔离

日期：2026-11-17（北京时间）。开始基线：07edea18a0177f828a0b6e4e74ee11ce0c9034c8。开始时 main 工作区干净，本地与 GitHub main 一致；依据 Day 21 已实施、验收和推送证据选择本日，不按触发次数递增。

## 当前实现摘要与最小方案

已有 PostgreSQL 持久运行归属、图检查点、审批主体/run/摘要/期限绑定、同事务工单与执行回执、租户范围文档检索。缺口是 HTTP 层仍用固定身份，无法由不同登录用户触发这些约束。

最小方案是复用 tenants.json 的四个种子账号和已有 AuthContext；独立口令从服务端配置读取，通过不透明会话 Cookie 得到不可变主体。每个主体复用自己的运行存储，不修改共享 store.context；已有数据库层继续执行资源归属校验。没有新服务、框架、数据库迁移或模型 API 调用。

## 五项验收与实测

- 匿名请求运行、工单及主体接口返回 401，伪造 X-User-ID/X-Tenant-ID 无效；health 仍公开。跨源 Origin 的写请求返回 403。额外的 role 请求字段被拒绝，账号与角色仅来自服务端种子数据。
- alpha 创建的运行，在 beta 与同租户 support-alpha 会话下读取、恢复均返回 404。本人可读取。引用只通过同一受保护 run 返回，替换 run ID 无法读取他人引用。
- 真实 PostgreSQL 中本人取得非空私有引用；四个主体的 search_docs 都取得本租户非空私有检索结果，且返回块的数据库租户归属不包含其他租户。没有文档原始文件的 HTTP 路径入口。
- 其他租户及同租户其他账号不能读取、批准、拒绝或执行本人的审批。本人批准后正常建单。跨租户工单详情为 404；同租户支持人员可读取工单，但不能审批其他用户动作。
- 登录令牌使用 HttpOnly / SameSite=Strict Cookie；重登轮换原令牌、退出撤销、1 小时后失效。浏览器实际完成 alpha 登录与运行，退出后 beta 登录，旧运行 GET 返回 404，页面旧运行数量为 0。服务器没有默认口令；未配置登录为 503，匿名业务访问仍为 401。

完整离线门禁 85 项测试通过。完整真实 PostgreSQL 回归 40 项通过；加强非空私有引用断言后，新增隔离测试再次通过。前端格式与构建结果、命令耗时及全部原始输出见验证 JSON；不把 ASGI 测试当浏览器网络验证，浏览器步骤另行记录。

## 资源 ID 入口核查

| 入口 | 身份与资源检查 |
| --- | --- |
| POST /runs | 会话主体选择存储，禁止请求体提供身份 |
| GET /runs/{id} | 内存按主体独立；持久查询 tenant/user/owner_context 完全匹配 |
| POST /runs/{id}/resume | 在检查点与调度之前加载同一归属记录 |
| run 的 citations、events、proposed_action | 随 run 一同授权，不提供任意路径文件读取 |
| search_docs 工具 | AuthContext 验证种子成员与角色；公共或本租户、版本、ready 条件过滤 |
| GET /tickets/{id} | member 本租户；support 仅服务端分配租户 |
| GET /approvals/{id} | requested_by 与关联 run 归属检查 |
| POST /approvals/{id}/approve 或 reject | 会话、本人/run/摘要/期限检查，模型和请求体身份无权代替 |
| POST /tickets | 按原审批重新检查主体/run/key/摘要，已有事务幂等约束不变 |
| CLI 导入、检索和 checkpoint_run | 仍是受信本机操作员入口，不伪装成远程用户 API |

## 复现

按 README 的 Day 22 配置方法在后端进程设置 SUPPORTOPS_DEMO_PASSWORDS，包含 user-alpha、support-alpha、user-beta、support-beta 四个互不相同且至少 12 字符的口令。不要把实际值或令牌放入 Git。启动后端与原前端，通过页面登录；同源 Vite 代理已实际验证，不引入 CORS 放行。

运行 `python scripts/check_offline.py`。数据库准备同 docs/database.md，显式设置驱动为 postgresql+psycopg、名称以 _test 结尾的 TEST_DATABASE_URL，再运行 `python -m unittest discover -s tests/integration -v`。只重现本日核心隔离测试可使用 `-p test_session_isolation.py`。测试自动创建唯一 schema、迁移并清理，不使用 SQLite 或跳过替代真实数据库。

浏览器复现夹具、进程与截图放在忽略的 output/day22-runtime 和 .playwright-cli。夹具只监听 127.0.0.1，使用测试源中的合成口令且强制 mock/内存模式；不向真实配置写入测试口令。临时进程完成后关闭。可按 scripts/check_offline.py 的同一环境运行单元测试测试入口，不需要真实模型密钥。

## 失败、修正和主要边界

首次完整数据库回归因为新增测试误写 repository 模块导入路径失败；修正为现有 packages.knowledge.repository.import_batch 后，单项与完整回归通过。首次 Prettier 命令因工作目录与相对路径不符未找到文件，改用现有本地可执行文件后完成格式与构建检查。失败原始记录保留，不删改为成功。

会话为单进程内存，最多 1024 个活跃令牌，固定 1 小时期限，重启后必须重登；没有多 worker 共享会话。全局每分钟最多 20 次登录尝试用于本机演示，不声称生产抗滥用能力。口令在启动时转为 PBKDF2-HMAC-SHA256（600000 轮）摘要，登录验证为同步计算，未测吞吐或密码校验并发性能。令牌随机生成，服务端仅保存 SHA256 摘要。

默认 Cookie Secure=0 只用于本机 HTTP；HTTPS 应启用 SUPPORTOPS_COOKIE_SECURE=1。没有公开部署、注册、密码重置、公开访客隔离（Day 48）或身份管理平台。错误配置会失败且不回显口令，缺少配置不会退回固定身份认证。

运行任务捕获对应 store 的不可变上下文；退出撤销会话与清空页面，不取消已被接受的后台任务。旧数据库记录只有在完整 owner_context 匹配时可读取，不为兼容旧角色分配而绕过授权。持久业务数据和图恢复边界仍遵循既有审批/key/事务机制，认证不意味着节点不会重放。

所有模型和数据场景为合成 mock；真实数据库与浏览器分别验证。本日没有调用付费 API，没有测量或宣称真实模型质量和生产安全认证。
