# Day33 会话上下文与产品版本偏好

通过现有会话 Cookie 访问。API 返回敏感的本机会话内容，服务端使用 `Cache-Control: no-store`。短期会话以服务端确认的完整执行上下文归属，不从请求正文接受用户或租户身份。持久偏好以租户和用户联合主键保存。

| 操作 | 数据与行为 |
| --- | --- |
| `POST /conversations` | 正文 `{}` 创建空上下文。持久模式可明确传 `{"use_preference":true}` 读取当前已确认版本。 |
| `GET /conversations/{id}` | 读取本人上下文、事实来源和最近四条输入。各输入的 run_id 可查原运行结果。 |
| `PATCH /conversations/{id}` | `{"product_version":"2.0"}` 明确更新。传 null 撤回。修订号递增，不从旧原文推断或恢复撤回的事实。 |
| `POST /runs` | 传 `knowledge:true` 和本人 `conversation_id` 使用当前版本。需要更正请先 PATCH，不同时传非空 `product_version`。 |
| `PUT /preferences` | 持久模式下仅接受 `{"product_version":"1.0","confirmed":true}`。无确认或类型不符返回 422。 |
| `GET /preferences`、`DELETE /preferences` | 读取或删除本人持久偏好。删除同步清除本人会话中仍从该偏好继承的值。其他主体与本人后来手动设置的会话事实保持原样。 |

短期会话独立于已有运行历史，最多 128 个，上限 1 小时且不续期。原始最近输入最多 4 条，每条沿用运行问题 2000 字符限制。当前事实只支持版本 1.0 或 2.0，来源区分显式会话更新与显式载入的已确认偏好。摘要由结构化事实生成，ASCII 上限 96 字节，对当前字节级分词而言是保守预算。记录数值为字节，未测量真实模型 token。摘要和旧原文留在查看接口；知识检索只消费结构化版本，避免旧文本把已更正内容重新带入模型。

短期状态随进程重启清空。长期偏好使用 Day33 Alembic 迁移，先执行 `alembic upgrade head` 并设置 `SUPPORTOPS_PERSIST_RUNS=1`。默认内存模式的长期偏好接口返回 409。

已接受的运行保存当时实际使用的版本，所以运行中更正、撤回或删除只影响之后的运行。删除偏好不删除既有运行、其中的引用，或后来手动设置的会话事实。当前入口通过 HTTP 使用，前端没有会话编辑界面。没有对话摘要模型调用和其他长期偏好类型。

在这套实现中，本轮上下文携带当前版本供检索。短期记忆保留会话事实和最近输入；长期记忆只保存明确确认的默认版本。知识库提供可引用的授权文档。向量缓存重用计算结果，不代表用户认可过的事实或偏好。
