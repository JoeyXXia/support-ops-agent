# Day31 五个结构规则与初标分歧

结构规则 `completion-citation-membership-v1` 检查正常完成、已有引用的成员关系，以及澄清或弃答时引用为空。它未比较问题意图与可用材料，因此 20 条都通过。助手初标只有 2 条充分可接受。下列五个案例来自 18 条分歧，待人类复核。

| 案例 | 实际行为与证据 | 结构规则漏掉的判定 |
| --- | --- | --- |
| ambiguous-429-01 | 问 429 原因，输出只追问版本，且没有编造原因 | 方向合理但不完整。还缺工作区及后续用量、日志核验，初标正确性和澄清均为 1。 |
| authentication-expiry-01 | 看到 `auth#errors` 仍弃答 | 来源已经区分 token 过期与限流。该输出没有否定按限流处理，也没有提供正确的认证排查方向。 |
| minute-reason-01 | 看到 `rate-limit#diagnosis` 仍弃答 | 题面给出了 20，来源支持按秒等待及有限重试；输出漏掉可执行下一步。 |
| monthly-exhaustion-01 | 看到 `monthly-quota#diagnosis` 仍弃答 | 此处关键是停止自动重试。只检查是否安全完成，会漏掉防止继续误操作的建议。 |
| upgrade-02 | 看到 `versions#versions` 仍弃答 | 依据直接解释升级不会重置月额度，回答却没有说明已用额度会保留。 |

两条商业问题的弃答得到初标认可，因为返回片段没有私有化定价或年度折扣证据。另跑未改写的旧 starter 问法，模型返回实际引用。它说明这条路径能够生成有据答案，但不计入开发集 20 条。结合 mock 的精确问法映射，证据已到达却弃答是本轮首先应关注的限制。
