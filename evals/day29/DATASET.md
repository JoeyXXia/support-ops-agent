# SupportOps Agent 合成数据卡 · day29-v1

这是 CloudDesk 演示的工程评测输入。内容来自仓库内的合成产品文档、工具契约和已实现的运行边界。每条记录的预期描述是验收意图，尚未执行评分。

| 类别 | 开发 | 最终 | 总计 |
| --- | ---: | ---: | ---: |
| 问答 qa | 20 | 20 | 40 |
| 工具 tool | 15 | 15 | 30 |
| 流程 workflow | 10 | 10 | 20 |
| 注入 injection | 7 | 8 | 15 |
| 权限与审批 auth | 8 | 7 | 15 |
| 合计 | 60 | 60 | 120 |

[问题簇源稿](groups.jsonl) 按具体问题及行为意图分组。每条源记录统一分配到一个分区，继承同一组的证据、预期与租户范围。已见开发习题的相近意图保留在开发侧，最终组按未作为开发示例的具体任务边界编写。两个分区各有 31 个簇。产品文档可被多个簇引用，评估的是新问题和行为场景。

[开发集](dev.jsonl) 用于修改 prompt 和调试评分器。[最终集](final.jsonl) 用于固定方案后的回归。发布的最终集在公开仓库可读取，不能视作保密的盲测。不要将其样例作为 prompt 示范，也不要用最终得分选择 prompt。规范化后用字符匹配阈值 0.84 检查跨分区近重复，并与 Day28 已知题目比对。低词面相似的语义改写仍需人工复核；共享产品知识也可能降低泛化难度。

- `answer` 需要仓库文档来源。`execute` 要求实际工具或流程结果。
- `clarify` 写明应追问的必要信息。`abstain` 写明缺少的证据或可接受说明。`refuse` 说明当前授权或契约边界。
- 租户字段只是评测 fixture 的范围提示。实际权限仍取可信主体。标注不构成越权或写入授权。
- 没有客户数据、真实密钥或真实 API 结果。没有对模型效果、通过率或生产性能做测量。

已发布 [版本与内容哈希](manifest.json)。从仓库根运行 `python -m scripts.freeze_day29` 可核对源稿、分组、覆盖和全部冻结字节。用 `python -m scripts.freeze_day29 --write --output-dir <空目录>` 可按规范复建。脚本拒绝覆盖不匹配的已有文件。已冻结的版本需保留，订正用新版本或独立勘误。
